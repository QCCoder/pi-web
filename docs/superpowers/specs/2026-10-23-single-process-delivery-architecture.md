## 1. 目标与当前事实

当前仓库仍使用 Next.js 与 pi-daemon 两个服务端进程，活跃会话由 daemon 持有。
本图讨论的目标是：把会话、子 agent 和 loop 的运行职责收回 Next.js 的常驻 Node.js 宿主，取消独立 daemon、会话 HTTP 代理、sidecar 启动与 daemon 健康探测。
会话管理、任务唤醒、停止和恢复仍保留为进程内模块；pi SDK、Extension 与工作区文件协议继续复用。

单进程指一个服务端执行宿主，不代表 bash、Git、测试工具不会创建命令子进程。
首版按常驻 Node.js、单实例部署讨论；不把函数即服务、Edge 或多副本部署包含在本次目标中。

## 2. 五个职责层

| 层 | 职责 | 实现与运行位置 |
| --- | --- | --- |
| ① 用户交互 | 会话、工作区、工作项进展、人工决策与配置 | pi-web React 界面；浏览器交互与 Next.js 页面渲染 |
| ② 应用接口 | HTTP 请求适配、身份与输入检查、SSE 事件订阅、会话操作 | pi-web Next.js API；直接调用本进程模块 |
| ③ 交付领域 | 工作项状态、就绪任务投影、领取、阶段交接、版本与证据检查 | pi-web 领域模块；API 与 Extension 复用同一套函数 |
| ④ 执行运行 | 会话注册、启动停止、loop 心跳、角色唤醒、角色资源装配、执行跟踪 | pi-web 进程内执行模块 + 嵌入其中的 pi SDK |
| ⑤ 文件与状态 | 工作项、产物、执行记录、工作区定义、会话 JSONL、临时运行态 | 本地工作区与 agentDir；Git 保存合适的历史 |

这些是职责层，不是五个服务或进程。②③④均在同一个 Next.js Node.js 宿主中执行。
③与④是业务判断和执行管理的边界：③判断是否可领、可交接；④负责创建、运行、停止和跟踪会话。

## 3. 执行层内部包含关系

Next.js Node.js 进程包含本仓执行管理模块，后者通过 SDK 创建 AgentSession。

- **Loop 触发模块**：复用现有 cron、到期判断、轮级锁和文件合同，改为在 Next.js 宿主幂等注册。
- **WorkerWaker**：发现角色存在可领取工作后唤醒角色；无就绪工作不调用模型。
- **RoleSessionLauncher**：根据工作区 Profile 装配角色职责、工具和上下文，创建 SDK 会话。
- **会话与执行管理**：统一普通会话、loop 轮与角色会话的注册、SSE、停止、执行记录和恢复信息。

上述前三项的新增或迁移不意味着创建独立服务。宿主启动、开发热重载和重复注册需要在后续实现中验证。

pi harness / SDK 提供 AgentSession、模型与工具循环、资源加载、Extension 机制、SessionManager 和基础工具。
设计、开发、测试与发布准备 agent 是使用不同 Profile 的会话实例；它们不是额外架构层，也不是四个 Extension。

pi-web 实现的工作项/交付、知识库、subagent Extension 加载到 SDK，作为工具入口。
交付工具调用③的领取与阶段服务；subagent 工具调用本仓的子会话执行管理，再使用 SDK 创建子会话。

## 4. 工作区与外部依赖

角色 Profiles、Skills、AGENTS.md、LOOP.md、STATE.md 与 delivery.yaml 保存在工作区，由宿主与 SDK 按职责加载。
禅道等外部来源仍通过工作区同步脚本调用工作项 API；不因取消 daemon 而重新内置 importer。
Git 仓库、worktree、测试环境和模型服务仍作为执行依赖。
工作项文件继续作为业务事实源，就绪任务池由其投影得到，不新增数据库写权威。

## 5. 明确的生命周期取舍

浏览器断开不要求结束服务端任务；关闭或重启 Next.js 宿主会中断该宿主持有的执行。
服务恢复后，依据持久化的工作项状态、产物、执行记录与版本进行接续，不承诺恢复内存中的模型调用或命令现场。
接手前仍需确认旧命令进程已停止；服务端退出不自动证明其启动的所有命令子进程均已退出。

迁移后的锁与并发方案应按实际写入者重新设计；不继续仅因为旧双进程布局而把所有调用都视为跨进程。
即使只有一个服务端进程，也仍需要防止并发请求、异步任务与重复触发造成重复领取或过期提交。
